# Запуск в GitHub Actions

1. Распакуйте весь архив в корень существующего репозитория и отправьте изменения в основную ветку. Сохраните папку `.github`. Установка Android Studio на компьютере не требуется.
2. Откройте **Actions → Android 14 Security Lab → Run workflow**. Выберите ветку и `mechanism`. Значение `all` запускает четыре независимых задания; `signature`, `source`, `microphone` и `usb` запускают выбранное задание.
3. По окончании скачайте артефакт `android14-<механизм>-<запуск>-<попытка>`. Распакуйте его и откройте `README.md` с поддержкой Markdown. Изображения содержат неизменённый кадр экрана. В `report.json` указаны реальные наблюдения и причины отсутствия доказательств.
После завершения задания **Сводный отчёт** доступен артефакт `report-android14-…`. Его README содержит изображения рядом с соответствующими опытами, выводы по выбранным механизмам и согласованные теоретические разделы.

4. Для проверки одного проблемного механизма начните новый запуск с этим значением. Параметры источников, разрешения и установленные пакеты принадлежат отдельному чистому AVD в каждом задании. Между опытами не выполняются перезагрузки.

## Приёмка результатов

| Задание | Обязательные снимки | Дополнительные условия |
|---|---|---|
| signature | 1.1, 1.2, 1.3 | Версии, хеши и причина отклонения обновления |
| source | 2.1 и 2.2 одного источника | Выключенный AppOp, атрибуция открытого APK, пакет отсутствует до и после |
| microphone | 3 | Выданное RECORD_AUDIO, выключенный глобальный доступ, свежее обращение диктофона |
| usb | 8.1 | Состояние переключателя согласуется с adb_enabled. Снимок 8.2 необязателен |

`PASS` требует всех обязательных доказательств. Подтверждённое противоречие ожидаемому поведению получает `FAIL`. Отсутствующий обязательный снимок, нераспознанный интерфейс или неподтверждённая техническая причина дают `INCONCLUSIVE`. Оба статуса завершают соответствующее задание с ошибкой. Соседние задания продолжаются; выгрузка доказательств выполняется и при ошибках.

В артефактах сохраняются XML перед захватом и после него, данные пакетов и диагностика сбоя. При неудачном основном источнике каталог с его именем содержит причину перехода к резервному приложению. В опыте 3 отдельные каталоги хранят записи каждой попытки. При отказе инфраструктуры до запуска Android подробности находятся в журнале job. Подтверждённые изображения прошлого запуска находятся в `evidence/42400869470-1/` и не копируются в новые результаты.

## Входные APK

Три подписанных образца находятся в `apks/`. Для них сохранены исходные проверки SDK Build Tools 35.0.0. Два сторонних APK загружаются из официальных GitHub Releases по фиксированным ссылкам в `apks/external.json`. Перед установкой скрипт проверяет SHA-256, подпись, имя пакета и версию. Команда ADB install используется только для подготовки стороннего приложения. Проверяемый образец в опыте 2 открывается из интерфейса выбранного файлового менеджера.

Резервный источник — Fossify File Manager 1.6.4, versionCode 16, SHA-256 `6e4656b8947966a2853681691bb0005e802ee89983fb141ec0f7186497dcd5f4`. Для просмотра Download на одноразовом AVD ему предоставляется доступ к общему хранилищу. [Релиз файлового менеджера](https://github.com/FossifyOrg/File-Manager/releases/tag/1.6.4)
